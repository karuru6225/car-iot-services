# 車のバッテリー上がり対策に、車載 IoT を自作した話① 基板設計・作成編

## 言いたいこと

メインバッテリーを上げて困り、結局 **専用基板まで作った**話です。

この編で持って帰りたいのは次の3つです。

- まず既製品で「送れる」ことを証明してから、ハードの自前化に進んだ

## 何が困ったか

車のメインバッテリーを何度か上げてしまいました。
サブやソーラー側の様子が見えないまま、メイン側が落ちる感じです。

やりたかったことはシンプルです。

- メインとサブの電圧を、遠隔で同時に見たい
- サブの充電量（電流・積算 Ah）も追いたい
- 車の近くに Wi-Fi がなくても動いてほしい
- 閾値変更やファーム更新を、毎回車まで行かずに済ませたい

市販モニタもあります。ただ「LTE でクラウドに残す」「設定をリモートで変える」「ハードまで自分で直す」まで含めると、私は自作の方が早いと判断しました。

---

## まずは既製品で経路を通す

いきなり基板は怖いので、M5Stack の既製品で「測れる・送れる・見える」を最短確認しました。

- M5Atom S3
- M5 Unit VMeter（実質 **1ch** の電圧）
- M5 Unit CatM（SIM7080G / SORACOM Cat-M）

Grove でつなぐと、車載12V → 分圧 → ADS → LTE → AWS IoT まで一気に通ります。
受信側（Terraform・S3・Athena）も **ほぼ同時**に立ち上げました（詳細は③）。ローカル表示だけで完結させなかったのは、あとで全部作り直すのが嫌だったからです。

BLE の温湿度計なんかもついでに拾える構成でしたが、本筋はバッテリーです。

ただし MVP の実害もすぐ見えました。

- メインとサブを **同時に**見れない
- サブの **充電量**が取れない
- DeepSleep 中も Cat-M が **通電したまま**で、サブを食う

経路の証明には十分。車載常設には足りない。ここから専用基板に進みました。

---

## 自作基板で「できること」

ユーザー（私）目線で言うと、だいたいこれです。

| できること | ざっくり |
| --- | --- |
| 電圧の同時監視 | メインとサブを同時に遠隔で見る |
| 充電量の把握 | サブの電流・電力・積算 Ah を追う |
| メインへの充電制御 | サブからメインへ。閾値で自動開始・停止も |
| 現地／リモート設定 | OLED＋ボタン、および Shadow／Jobs（②③） |
| 常設しても食いすぎない | DeepSleep 中は通信モジュールの電源も落とす |
| リレー制御（おまけ） | 外部リレーを駆動できる口も空けてみた |

MVP で足りなかった穴を埋めるのが目的です。リレーは必須というより「ついでに口を空けた」くらいです。

## 回路と基板で意識したこと

KiCad で設計し、**JLCPCB の PCBA 前提**で部品を選びました。
定数の細部はリポジトリの `m5atom_power_adc/CIRCUIT.md` に逃がします。ここでは判断だけ書きます。

**実害 → 対処**はこんな感じです。

- ケーブルだらけ・1ch・充電量なし・常時通電 → ESP32-S3 直付け、2系統電圧、INA228、LTE のパワースイッチ
- アナログがガタつく → デジタル用とアナログ用の 3.3V を **別 LDO**（同じ AMS1117 を2個）。アナログ側はフェライト経由
- DC-DC のノイズ → スイッチング領域と計測領域を離す。スイッチングノードは **面積を小さく**しつつ、電流に見合う太さも確保
- Grove／リレーが複数系統 → KiCad の **階層シート**で回路を使い回し。部品番号も階層に紐づけて、PCB レイアウトも横展開しやすくした

MCU は最初 M5Atom 外付け案もありましたが、最終的に ESP32-S3-MINI-1 のカステレーション直付けにしています。

トレース幅の目安（1oz）だけ載せます。細部は `HARDWARE.md` 側です。

| 用途 | 目安 |
| --- | --- |
| +12V／スイッチング付近 | 1.5mm |
| +5V | 0.8mm |
| +3.3V デジタル | 0.5mm |
| アナログ・信号 | 0.3mm |

## 試作で抵抗が焼けた

JLCPCB に流して到着、通電したら……抵抗が焼けました。

原因は痛いほど単純で、いくつかの定数指定をミスして **100kΩ のはずが 100Ω（`k` 抜け）** になっていたことです。
机上レビューでは拾いにくく、実機通電で一気に可視化されるタイプのミスでした。

見た目は無事でもおかしい個体があり、そこで **サーモカメラ**が役立ちました。
設計上そんなに熱くならないはずのところがホットスポットになり、そこを追うとまた桁ミスの抵抗が見つかる、というパターンです。
目視やテスタだけだと「静かに間違っている部品」は拾いにくいので、発熱という結果から逆算できたのが大きかったです。

BOM を洗い直して再発注。「一発正解」より「壊せる試作 → 正す → 次ロット」の方が速い、というのが学びです。

（サーモ画像は執筆時に配置予定）

そのあと、試作基板の寸法で Fusion 360（個人用途）の筐体も起こしました。むき出しは怖いので。動く基板があるから筐体が作れる、という順番でした。

## まとめ

- メイン上がりが動機。遠隔で電圧と充電量を見たいところから始めた
- 既製品 MVP で LTE〜クラウドまで通し、足りない点（1ch・Ahなし・常時通電）をはっきりさせた
- 専用基板でそれを埋め、初回は `k` 抜けで焼けた。サーモも助けた
- ノイズはゾーン分離・電源分離・ループ面積。配線太さは電流に応じて
