# 車のバッテリー上がり対策に、車載 IoT を自作した話② ファームウェア開発編

## 言いたいこと

車載ファームで一番効いたのは、**OTA を最初に固めたこと**です。理由は高尚ではなく、**車までモジュールを取りに行くのがめんどくさいから**です。

ついでに押さえておきたいのが次です。

- 証明書や device_id はファームに焼かない（S3 **公開バケット**で OTA するため）
- ビルドは PlatformIO。タグ push で GitHub Actions → 配布 → Jobs まで自動化
- Cat-M は細いので、ペイロードは短くした（最終的に MessagePack でおおよそ 59 bytes）

シリーズはハード／ファーム／インフラの3本です。OTA・キッティングだけ欲しい人は、この編だけでも大丈夫です。

| # | 編 |
| --- | --- |
| ① | ハード（基板・試作） |
| ② | **本編**（ファーム） |
| ③ | インフラ（Terraform・Grafana） |

対象コードは `esp32_iot_gateway` です。①の試作基板の上で動いています。

## 土台：PlatformIO と「焼かない」設計

ビルドは **PlatformIO** にしました。ライブラリ管理がやりやすそうだったのが理由です。`platformio.ini` で develop / release を分けられるのも後から効きました。

コードは早めに device / domain / service に分けています。教科書的な話はここまで。

ほぼ同時に、**デバイス固有情報をファームから分離**しました。
理由は単純で、**OTA を S3 の公開バケットでやりたかったから**です。バイナリに証明書が入っていると公開配信できません。

なので証明書は SPIFFS、device_id や MQTT ホストなどは NVS。キッティング（`ops/provision_device.ps1`）で個体ごとに書きます。「ファームは全員同じ URL、個体差はキッティング」です。

## 普通の1サイクル

起動〜 DeepSleep はざっくりこうです。

1. 周辺初期化
2. LTE 接続
3. **OTA / Jobs チェック**（ここが先）
4. 計測して MQTT / Shadow
5. LTE 切断 → 寝る（おおよそ5分）

あとから入れた運用寄りの話です。

- 寝る時刻を **UTC の5分境界**に寄せる（グラフが揃う）
- 圏外なら RTC／SPIFFS に溜めて、復帰後に送る
- DeepSleep 前にモデム電源も落とす（①の「常時通電」問題つぶし）

ペイロードの生 JSON は出しません。要点だけ言うと、最初はフィールド名を短くし、そのあと MessagePack にしました。実測でおおよそ **59 bytes** まで落ちています。
クラウド側（ingest）で展開して S3 にはフルネームで保存するので、Glue / Athena を毎回いじらなくてよい、という分け方です。

## OTA を最優先で固めた

USB で書くたびに車へ行く開発は続きません。なので AWS IoT Jobs で「次のジョブありますか？」を起床時に聞き、あれば HTTPS で落として app0/app1 に書いて再起動、を先に作りました。起動後に MQTT が確認できなければロールバックします。

実装は一発では終わりませんでした。だいたいこの順です。

1. まず疎通（モデムの MQTT まわりでハマる）
2. ダウンロード経路を安定させる
3. OLED に進捗・失敗を出す
4. **gzip** で配って端末で解凍（あとで高速化）
5. Jobs 共通化し、OTA と「Ahリセット／充電」などのコマンドを分ける

「OTA がある」と「車載のまま短サイクルで直せる」のあいだには、これくらいの道のりがありました。
失敗したファームが残るのは怖いので、2スロットとロールバックは早めに入れています。

---

## GitHub Actions まで自動化する

OTA だけでは運用が回りません。`vX.Y.Z` タグを push すると Actions がビルドし、`firmware.bin.gz` を公開バケットへ置き、Jobs を作り、Release にも添付します。

- AWS 認証はアクセスキーではなく **OIDC**
- 配信対象は Thing グループ所属で制御

DeepSleep 中の端末は、次に起きたときに Jobs を拾って勝手に更新されます。ここまで来てやっと「取りに行かなくてよい」が実感できます。

---

## 余談：現地メニュー・Shadow・基板 v2

車のそばでは OLED＋2ボタンのメニュー（Ah オフセットやセンサー表示など）を使います。
遠くからは Shadow desired と Jobs で閾値やコマンドを飛ばします（画面の話は③）。

なお **基板 v2 は開発中**です。いまの運用は v1 寄り。
ピン差は `board_pins` とキッティングの `board_version` で吸収する仕込み、自己保持（PWR_HOLD）まわりの処理は FW 側を先に入れ始めています。
メイン電圧が危なくなったら回路ごと電源を断つ、はまだこれからです。①の「メイン上がり」への次ロット寄りの答え、という位置づけです。

## まとめ

- OTA 最優先の動機は、車まで取りに行くのがめんどくさいから
- 公開バケット配信のため、秘匿情報はキッティングに分離した
- タグ push でビルド〜Jobs まで自動化した
- Cat-M 向けにペイロードを短くした

次は **③インフラ編**です。MVP とほぼ同時にクラウドを立ち上げた話と、いま Grafana で見ている話です。
